## Goal
Make every error response follow the API contract from `backend-core`: `{"error": "<message>", "code": "<machine.code>", "requestId": "<id>"}`, and return **409 Conflict** for optimistic-locking conflicts (`user.ErrConflict`) instead of 422. Covers pending items 2 and 3 of the `backend-go` skill.

## Decision log

### Error codes are `<context>.<snake_reason>`, defined next to the mapping that uses them
```go
// before — clients could only branch on the message text
{"error": "user: version conflict"}

// after
{"error": "user: version conflict", "code": "user.version_conflict", "requestId": "0199d4a1-..."}

// user/http/errors.go
const codeVersionConflict = "user.version_conflict"
case errors.Is(err, user.ErrConflict):
	platformhttp.WriteError(w, r, http.StatusConflict, codeVersionConflict, err.Error())
```
**Why:** messages are for humans and can be reworded at any time; a client that parsed `"user: version conflict"` would break silently. Codes are the stable contract, so they are constants owned by each context's `http` package (where `writeDomainError` lives) — `platform` cannot import a context. Codes that are not tied to a context (`request.invalid_body`, `internal_error`) live in `platform/http`. All four validation sentinels share `user.invalid` because the client fix is the same (correct the input) and the message already says which field; split it if a client ever needs per-field handling.

### Stale version (`ErrConflict`) moves from 422 to 409
```go
// before — grouped with field validation
case errors.Is(err, user.ErrInvalidName), ..., errors.Is(err, user.ErrConflict), ...:
	WriteError(w, http.StatusUnprocessableEntity, err.Error())
// after — its own case
case errors.Is(err, user.ErrConflict):
	WriteError(w, r, http.StatusConflict, codeVersionConflict, err.Error())
```
**Why:** the request is valid; it lost a race with another write. 422 tells clients "fix your payload", which is the wrong recovery — 409 means "refetch the resource and retry". Clients distinguish the two 409s by `code` (`user.version_conflict` vs `user.email_already_exists`). This is a contract change for `PUT /users/{id}` callers.

### 500s go through `WriteInternalError`, never through `WriteError` with `err.Error()`
**Why:** unmapped errors can carry driver or SQL details. One helper both logs the real error with `request_id` and returns a fixed message, so the leak is impossible by construction rather than by reviewer attention. The returned `requestId` is what support uses to find that log line.
